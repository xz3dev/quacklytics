Every Quacklytics instance serves a read-only [Model Context Protocol](https://modelcontextprotocol.io) endpoint at `/api/mcp`. An agent connected to it can read the events, schema, saved insights and dashboards of all your projects, and then run its own analytical queries with DuckDB.

## Connect an agent

Agents sign in with OAuth, the way the MCP specification describes. You add the endpoint to your agent, it opens Quacklytics in your browser, and you sign in and approve it. There is no token to copy.

<Steps>

1. Add the server to your agent. The **Projects** page shows these commands with your endpoint under **Agent access (MCP)**.

    For Claude Code, run the following, then run `/mcp` in Claude Code, select `quacklytics` and choose **Authenticate**:

    ```sh
    claude mcp add --transport http quacklytics https://analytics.example.com/api/mcp
    ```

    For Codex:

    ```sh
    codex mcp add quacklytics --url https://analytics.example.com/api/mcp
    codex mcp login quacklytics
    ```

    Other clients need Streamable HTTP and OAuth support. They find everything else themselves: the endpoint's `401` response points to `/.well-known/oauth-protected-resource/api/mcp`, which names Quacklytics as the authorization server, and the agent registers itself there.

2. Your browser opens Quacklytics. Sign in if you aren't already.
3. Check the request and select **Allow access**. The agent receives its access and is ready to use.

</Steps>

The approval page shows the name the agent gave itself and where its access goes, for example an app on this computer. Allow only agents you just started connecting yourself: anyone can make an agent ask for access, and the name is its own choice.

An approved agent reads every project of the user who approved it. Its access tokens last an hour and it renews them on its own, so it stays connected while you use it. Under **Connected agents** on the **Projects** page, **Disconnect** rejects the agent's next request and makes it ask for approval again. Dataset URLs the agent already received stay valid until they expire, at most an hour later, and data it already downloaded stays with the agent.

<Aside>
    Agents sign in only when `APP_ORIGIN` uses HTTPS, or a loopback address such as `http://localhost:3000` for local use. On other origins agent access is off and the **Projects** page says so; the rest of the app works as usual.
</Aside>

<Aside>
    Agents that were set up with a Quacklytics access token (`Authorization: Bearer qmcp_…`) stop working after upgrading, because the tokens are deleted. Remove the header from the agent's configuration and connect it again.
</Aside>

<Aside type="caution">
    Ingestion keys are public, since they are embedded in your website, so they never grant read access.
</Aside>

## Tools

Every tool except `get_query_guide` takes a `project` argument: a project id from `list_projects`.

| Tool | Returns |
| --- | --- |
| `list_projects` | Ids and names of the projects the agent can read |
| `get_dataset` | `setupSql` that defines the DuckDB view `events` over signed Parquet URLs covering every event |
| `get_schema` | Event types with their property names and types |
| `list_insights`, `get_insight` | Saved insights and their full definitions |
| `list_dashboards` | Dashboards and the insights on them |
| `get_query_guide` | DuckDB setup, columns, JSON property access and example queries |

## How the data is put together

Quacklytics publishes completed days to S3 as one Parquet file per UTC month. Everything else is still only in its database: today, months not yet published, and months that changed since publishing.

`get_dataset` reads both inside one database transaction. It writes the unpublished rows to a temporary Parquet file in your bucket, and its `setupSql` reads that file and the published months through signed URLs. Together they cover every event exactly once. Mixing data from different calls could count events twice or miss them, so to get fresh data the agent calls `get_dataset` again and reruns its `setupSql`.

- A snapshot is reused for up to 10 minutes, so the newest events can arrive a few minutes late. Repeated calls in that window return the same snapshot with newly signed URLs instead of uploading another file. `capturedAt` says when the snapshot was taken.
- URLs expire at `expiresAt`, at most an hour after the snapshot. The temporary file is deleted automatically within about two hours.
- The agent needs no S3 credentials. DuckDB reads the signed HTTPS URLs directly.
