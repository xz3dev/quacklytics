Every Quacklytics instance serves a read-only [Model Context Protocol](https://modelcontextprotocol.io) endpoint at `/api/mcp`. An agent connected to it can read the events, schema, saved insights and dashboards of all your projects, and then run its own analytical queries with DuckDB.

## Connect an agent

<Steps>

1. Open the **Projects** page and, under **Agent access (MCP)** below the project list, select **Create access token**.
2. The new token opens revealed, with setup instructions for Claude Code and Codex. You can reveal it again later with the eye button.
3. Add the server to your agent. For Claude Code:

    ```sh
    claude mcp add --transport http quacklytics https://analytics.example.com/api/mcp \
      --header "Authorization: Bearer qmcp_…"
    ```

    For Codex, add it to `~/.codex/config.toml`:

    ```toml
    [mcp_servers.quacklytics]
    url = "https://analytics.example.com/api/mcp"
    http_headers = { Authorization = "Bearer qmcp_…" }
    ```

    Other clients need the same two things: the endpoint URL with the Streamable HTTP transport, and an `Authorization: Bearer` header.

</Steps>

A token belongs to the user who created it and reads every project, so one connection covers all of them. Revoking it on the same page rejects its next request. Dataset URLs the agent already received stay valid until they expire, at most an hour later, and data it already downloaded stays with the agent.

<Aside>
    Before 0.6.0, tokens were created per project on the ingestion page. Upgrading deletes them, so create a new token and update your agent's configuration.
</Aside>

<Aside type="caution">
    Ingestion keys are public, since they are embedded in your website, so they never grant read access. Treat MCP tokens like passwords.
</Aside>

## Tools

Every tool except `get_query_guide` takes a `project` argument: a project id from `list_projects`.

| Tool | Returns |
| --- | --- |
| `list_projects` | Ids and names of the projects the token can read |
| `get_dataset` | `setupSql` that defines the DuckDB view `events` over signed Parquet URLs covering every event |
| `get_schema` | Event types with their property names and types |
| `list_insights`, `get_insight` | Saved insights and their full definitions |
| `list_dashboards` | Dashboards and the insights on them |
| `get_query_guide` | DuckDB setup, columns, JSON property access and example queries |

## How the data is put together

Quacklytics publishes completed days to S3 as one Parquet file per UTC month. Everything else is still only in its database: today, months not yet published, and months that changed since publishing.

`get_dataset` reads both inside one database transaction. It writes the unpublished rows to a temporary Parquet file in your bucket, and its `setupSql` reads that file and the published months through signed URLs. Together they cover every event exactly once. Mixing data from different calls could count events twice or miss them, so to get fresh data the agent calls `get_dataset` again and reruns its `setupSql`.

- A snapshot is reused for up to 10 minutes, so the newest events can arrive a few minutes late. Repeated calls in that window return the same snapshot with newly signed URLs instead of uploading another file. `capturedAt` says when the snapshot was taken.
- URLs expire at `expiresAt`, at most an hour after the snapshot. The temporary file is deleted automatically within about two hours.
- The agent needs no S3 credentials. DuckDB reads the signed HTTPS URLs directly.
